# SRW64 tests

The tests compile 64-bit Windows (and Linux) programs, recompile them using SRW64, build the recompiled programs and compare their output with the output of the original programs.

Requirements: NASM, MinGW-w64 (`x86_64-w64-mingw32-gcc`, `dlltool`, `windres`), Wine, GCC, GNU ld, Python 3, static glibc (`libc.a`, for the Linux test -- it is skipped when not available).

    ./run_tests.sh

Environment variables:

* `SRW64` -- path to SRW64 executable (default: `../SRW64.exe`)
* `WORK` -- work directory (default: new temporary directory)
* `WINDOWS_DIR` -- directory with original Windows executables (*sort.exe*, *where.exe*), for example `/mnt/windows/Windows/System32` -- enables test of executables compiled by Microsoft
* `FH4_EXECUTABLES` -- list of executables built by Visual Studio 2019+ (with `__CxxFrameHandler4`), their C++ exception handling data is verified after recompilation
* `SYSTEM_TOOLS` -- non-empty value enables test of Linux system tools of the distribution (*sort*, *gzip*, *sed*, *grep*, *xz* -- dynamically linked, usually stripped PIE executables)

Tests:

* *mingw_c* -- C program compiled by MinGW (recompiled including CRT startup code): switch tables, function pointers in data, callbacks, floating point, imports -- win64 executable is run using Wine
* *msvc_patterns* -- freestanding program with code patterns generated by MSVC (image relative jump tables, two-level jump table with byte index table, image relative array addressing) and GCC jump table -- win64 executable is run using Wine, elf64 version is linked with *runtime_linux.c* (implementation of used Windows functions) and run natively on Linux
* *fh4* -- C++ exception (catch block with continuation address relative to function start) described by `__CxxFrameHandler4` data -- the recompiled code is shorter, so the program works only if the offsets in the data are converted; the data is also verified by *verify_fh4.py*
* *linux_cpp* -- statically linked Linux C++ program with exceptions (built with `-O0` and `-O2`): class hierarchies, rethrow, nested handlers, destructors during unwinding, function-try-block, `std::function`, `exception_ptr` from another thread, `bad_alloc`, `bad_cast` -- works only if the new `.eh_frame` and exception tables are correct
* *linux_dynamic* -- the Linux C and C++ programs linked dynamically (`-no-pie` and `-pie`): imports through PLT and GOT, COPY relocations, data relocations with symbols, relative relocations, C++ exceptions through shared libstdc++
* Linux system tools (optional) -- *sort*, *gzip*, *sed*, *grep*, *xz* of the distribution (functions only from `.eh_frame`, RELR relocations, AVX-512 functions kept in original code, threads, PCRE JIT)
* *linux_c* -- statically linked Linux C program (`gcc -static -no-pie`): switch tables, function pointers, callbacks, varargs, floating point, thread local storage, threads, setjmp/longjmp, atexit handlers and glibc internals (IFUNC resolvers, CET instructions, AVX-512 functions which are kept in original code) -- the recompiled program is run natively
* executables with `__CxxFrameHandler4` data (optional) -- the data is verified by *verify_fh4.py*
* Windows executables (optional) -- *sort.exe* and *where.exe* from Windows 10/11

Scripts:

* *roundtrip_win64.sh* -- recompiles any 64-bit Windows executable into new Windows executable: `roundtrip_win64.sh <executable> <work directory> [console|windows]`
* *roundtrip_elf.sh* -- recompiles 64-bit Linux executable (statically or dynamically linked) into new Linux executable: `roundtrip_elf.sh <executable> <work directory>`
* *mkstubs_elf.py* -- creates stub libraries for linking of recompiled dynamically linked Linux executable: `mkstubs_elf.py <name>.imports <directory>` (prints linker arguments)
* *fixup_elf.py* -- post-link fixups of recompiled Linux executable (COPY relocations moved to the original addresses, program headers of the original executable): `fixup_elf.py <recompiled executable> <name>.imports <name>.phdrs`
* *mkimplibs.py* -- creates import libraries for the imports used by the generated assembler file
* *verify_fh4.py* -- compares `__CxxFrameHandler4` data of original and recompiled executable: `verify_fh4.py original.exe recompiled.exe`
* *compare_ida.sh* -- compares jump tables and decoded code of SRW64 with the analysis of IDA Pro (headless): `IDAT=<path to idat> compare_ida.sh <executable> <work directory>` (exit code 0 = no differences, 1 = differences to check)
* *ida_export.py* -- IDAPython script for headless IDA (used by *compare_ida.sh*): exports functions, code ranges and switches, or decompiles all functions using Hex-Rays (`SRW64_IDA_MODE=decompile`, more IDA processes can decompile in parallel, each with its own copy of the database)
* *compare_ida.py* -- compares the lists written by SRW64 (`--list_jump_tables`, `--list_code_ranges`) with the files exported by *ida_export.py*: `compare_ida.py <executable> <jump tables> <code ranges> <IDA export directory> [number of details]`
